# 摄影集照片筛选器 · 软件设计

版本 v0.1 ｜ 2026-10-16 ｜ 配合《需求分析》阅读

## 1. 界面结构

界面有两个状态，由目标文件夹面板头部的「展开 / 收起」按钮切换。

```
【浏览模式】按下「展开」之前

┌──────────┬───────────────────────────────┬──────────────────┐
│ 目录树    │ 素材照片信息 ｜ 缩放            │ 目标文件夹   ▾    │
│          ├───────────────────────────────┤ （小缩略图网格）   │
│ ▾ 照片_    │                               │                  │
│   Leica_  │        素  材  大  图          │  头部有「展开」按钮 │
│   M10     │                               │                  │
│   ▸ 095_  │                               │                  │
├──────────┴───────────────────────────────┴──────────────────┤
│ ▾ 095_2026_0929 [□][□][□]  ▾ 096_2026_1001 [□][□][□] ← 素材照片│
└─────────────────────────────────────────────────────────────┘

【整理模式】按下「展开」之后

┌──────────┬───────────────────────────────┬──────────────────┐
│ 目录树    │ 目标文件夹的基本信息            │                   │
│          ├───────────────────────────────┤      垃圾桶        │
│          │ 目标文件夹的缩略图（更大）       │                   │
│          │ 可拖动排序，白线标记落点          │  ← 分隔条可左右拖动 │
├──────────┴───────────────────────────────┴──────────────────┤
│ 目标文件夹的照片  ← 横向滚动                                   │
└─────────────────────────────────────────────────────────────┘
```

| 区域 | 浏览模式（收起） | 整理模式（展开） |
| --- | --- | --- |
| 顶部 | 菜单栏 + 快捷工具栏：重新选择工作区、撤销/重做、缩放 | 同左 |
| 左栏 | 素材目录树：根目录 → 子文件夹 → 子文件 | 同左 |
| 中栏上方 | 素材照片信息：文件名 · 路径 · 像素 ｜ 缩放 | 目标文件夹的基本信息 |
| 中栏 | 素材大图，方向键连续过片 | 目标文件夹的缩略图，更大，可拖动排序 |
| 右栏 | 目标文件夹的小缩略图网格，头部有「展开」按钮 | 垃圾桶 |
| 底栏 | 素材照片，按子文件夹分组，每组可收起 | 目标文件夹的照片 |

交互要点：

- 左栏**双击某个文件夹**，底部的素材照片条同步跳转到那一组
- 右栏与中栏之间的**分隔条可以左右拖动**，自己分配宽度
- 整理模式下拖动照片排序，落点用**白线**标出，插入完成后编号才重算

### 配色（取自 Capture One 22 界面实测取样）

| 用途 | 色值 |
| --- | --- |
| 大图区背景（最深） | `#191919` |
| 面板 / 工具栏 / 胶片条底色 | `#2D2D2D` |
| 高亮与选中 | `#414141` |
| 正文文字 | `#C3C3C3` |
| 次要文字（文件名等） | `#A0A0A0` |

全部集中在 `ui/theme/Theme.java` 里定义，不散落在各个组件中。

## 2. 分层与包结构

```
com.photoselector
├── app    启动与依赖装配
├── core   领域模型：Photo / PhotoGroup / TargetFolder / NumberingRule / UndoStack
├── io     文件与图像访问：ImageSource、缩略图与缓存、导出器
└── ui     Swing 界面
```

**约束：`core` 与 `io` 不得 import 任何 Swing 类。**

这不是洁癖，有两个实际收益：挑选逻辑、编号规则、目标序列这些都能脱离界面写单元测试；
以后即使更换界面框架，业务逻辑也不需要改动。

## 3. 核心域模型

### 3.1 Photo（不可变）

描述一张源照片：源文件路径、所属组、像素宽高、类型（JPG / DNG）。
不可变意味着它一旦创建就不会被修改，所有状态变化都发生在别处，便于推理和测试。

### 3.2 PhotoGroup

一个子文件夹 = 一个组。持有该组的照片列表和折叠状态。
胶片条上每个可收起的框就是一个 `PhotoGroup`。

### 3.3 目标文件夹即工作区（没有中间层）

这里**没有「挑选计划」这种中间状态**。所有改动都直接落到目标文件夹上，
磁盘上的真实内容就是界面上看到的内容。

| 界面操作 | 磁盘上发生的事 |
| --- | --- |
| 浏览模式下挑中一张素材 | 立刻复制进目标文件夹，按编号规则命名，追加到末尾 |
| 整理模式下拖动排序 | 重命名受影响的那一段文件 |
| 把照片拖进垃圾桶 | 移出目标文件夹，放进本次会话的垃圾桶目录 |
| 关闭程序 | 清空垃圾桶目录 |

这样做的最大好处是**简单**：界面不需要维护一份和磁盘平行的状态，
也就不存在"两边对不上"的问题，正好呼应第 4 节那条原则。

代价是**没有"导出"这道确认关口**——每一下操作都是真的在动磁盘，
所以安全措施必须内建在每一步操作里，见第 8 节。

### 3.4 状态与撤销

素材照片只有两种状态：**未处理** 和 **已加入目标文件夹**。
后者不是一个记在内存里的标记，而是直接以「目标文件夹里有没有它」为准——
又一次回到第 4 节那条原则。

这里没有"排除"这个概念：素材文件从头到尾不会被修改，
所以对它的任何标记都只是临时的显示辅助，不值得做成一套体系。

撤销栈记录的是**已经发生的磁盘操作**（复制了哪张、重命名了哪一段、移除了哪张），
撤销就是把它们反向执行回去。由于每一步都真实落盘，撤销必须同样可靠。

### 3.5 编号规则（可配置）

`NumberingRule` 持有三个参数：起始值、步进、补零位数。
默认 `起始 10 / 步进 10 / 补零 4 位`，即 `0010`、`0020`、`0030` ……

## 4. 工作区与启动流程

### 4.1 一条原则

配置只记录「你选了什么」，画面永远反映「磁盘上真实有什么」。

### 4.2 启动流程

```
启动
 │
 ├─ 读取上次的工作区配置
 │
 ├─ 没有配置 ──> 打开「选择工作区」界面
 │                 · 选素材根文件夹
 │                 · 在树下打勾，决定哪些子文件夹纳入范围
 │                 · 选目标文件夹
 │                 · 确认后进入主界面
 │
 └─ 有配置 ──> 直接进主界面，但先与磁盘对账：
                 素材根目录不存在     → 退回「选择工作区」并说明原因
                 某条剔除项不存在     → 忽略该项，其余照常
                 目标文件夹不存在     → 提示后要求重新选择
                 目标文件夹内容有增减 → 以磁盘实际内容为准重建显示
                 垃圾桶目录里有残留     → 启动时清空
```

### 4.3 配置存放位置

`%APPDATA%\PhotoSelector\workspace.properties`，用 JDK 自带的 `java.util.Properties` 读写。

选它的理由：不引入任何依赖；文件是纯文本，你可以直接打开看里面记了什么，出问题也好排查。

### 4.4 「选择工作区」界面

- 与主界面左栏共用同一套「目录树 + 打勾」组件，不重复实现两遍
- 顶部工具栏提供「重新选择工作区」入口，打开的是同一个界面
- 更换目标文件夹时，原有的整理结果如何处理，见第 9 节

## 5. 图像来源抽象 —— DNG 之所以能"往后放"

```java
public interface ImageSource {
    String fileName();
    int width();
    int height();
    BufferedImage loadFull();               // 大图视图使用
    BufferedImage loadThumbnail(int height); // 胶片条与右栏使用
}
```

第一版只实现 `JpegImageSource`（`ImageIO` 直接读取）。
以后新增 `DngImageSource`（解析 TIFF 的 IFD 链表、取出内嵌的全尺寸 JPEG 预览），
**界面层一行都不用改**。这是"先不做 DNG"能成立的技术前提。

## 6. 线程模型

Swing 有两条铁律，必须从一开始就守住：

1. 所有界面改动只能在事件分发线程（EDT）上做
2. 读文件、解码、缩放这些耗时的活，绝不能放在 EDT 上

```
EDT（界面线程）                后台线程池（CPU 核数 - 1）
     │                               │
     │  请求缩略图 ─────────────────>  读文件 → 解码 → 缩放
     │                               │
     │  <───── SwingUtilities.invokeLater 回传结果
     │  更新界面
```

在此之上加**预取**：当前看第 N 张时，后台已经把 N+1、N+2 张解码好了，翻页就是瞬时的。

## 7. 缓存与渲染性能

缩略图缓存分两层：

- 内存：固定容量的 LRU，存放最近用过的几百张
- 磁盘：缩略图文件，键 = 文件路径 + 文件大小 + 最后修改时间

两个具体的性能要点：

- **胶片条自绘**。一个组可能有 313 张，如果给每张都放一个 `JLabel`，
  Swing 要维护几百个组件。正确做法是重写 `paintComponent`，只绘制当前可见范围内的缩略图。
- **目录树懒加载**。展开某个文件夹节点时才去读它的子项，避免启动时扫描上万条目录项。

## 8. 即时生效下的安全设计

所有改动都直接写在目标文件夹上，没有"导出"这道确认关口，
所以安全措施必须内建在每一步操作里：

1. **删除走系统回收站**。清空垃圾桶时不做永久删除，改送系统回收站。
   万一你误删的是原本就放在目标文件夹里的照片，还能找回来。
2. **两阶段重命名**。批量重排编号时，先把待改文件统一改成临时名，
   再改成最终名，避免 A 改 B、B 改 A 的互相覆盖。
3. **源素材只读**。素材文件夹里的文件永远只被读取，不移动、不删除。
4. **重名不静默覆盖**。复制进目标文件夹时若已存在同名文件，先问，不自作主张。

### 已确认

- 「展开」按钮的语义：目标文件夹的缩略图移到中间放大，供精细筛选
- 右栏位置暂定为垃圾桶：拖入即从目标文件夹移除，关闭程序时清空
- 没有挑选计划，所有改动直接落到目标文件夹
- 目标序列支持拖动排序，拖动时用白线标记落点，**插入完成后**才实时重算编号
- 启动时无配置则进入「选择工作区」；有配置则恢复，并与磁盘实际内容对账
