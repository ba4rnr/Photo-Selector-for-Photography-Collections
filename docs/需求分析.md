# 摄影集照片筛选器 · 需求分析

版本 v0.1 ｜ 2026-10-16 ｜ 状态：初稿，待确认事项见第 6 节

> 界面交互细节在《软件设计》中进一步细化，两者如有出入，以《软件设计》为准。

## 1. 项目定位

一个本地运行的桌面工具，服务于「拍摄 → 挑片 → 归档成片」这条个人流程中**挑片**这一环。

它不替代 Lightroom / Capture One 的调色出片能力，只解决一件事：**从几百张原始文件里快速挑出要留的，按既有归档规则输出到目标文件夹。**

## 2. 现状调研（基于真实素材）

| 素材来源 | 格式 | 命名 | 规模 |
| --- | --- | --- | --- |
| Leica M10 `D:\照片_Leica_M10` | 纯 DNG，平均 25 MB | `L100xxxx.DNG` | 单个拍摄文件夹 61–313 张 |
| Ricoh GR IV `D:\照片\GR IV` | DNG 与 JPG 分目录存放、同名配对 | `R000xxxx` | 257 DNG + 253 JPG |
| 胶卷 / 小机器 | JPG（冲扫或机出） | 8 位连续编号 | 单卷约 35 张 |

归档习惯：

- 源文件夹按 `编号_日期` 排列，如 `095_2026_0929`
- 挑出来的成品进 `000_成片X`，内部再按 `编号_日期` 分子目录
- 保留率低，一个几百张的拍摄文件夹最终只留 1–47 张
- **没有** Lightroom 目录，**没有** XMP 边车文件

由此得出一个关键判断：现有流程里不存在「星级 / 色标 / 关键词」这一环，
实际语义只有「要」和「不要」两种。工具设计应当贴合这个习惯，而不是引入一套更重的标记体系。

## 3. 功能需求

### 3.1 范围选择

- 选择一个根文件夹作为工作范围
- 从根文件夹的**直接子文件夹**中勾选要剔除的项，可多选
- 未被剔除的子文件夹即为本次工作实际覆盖的范围
- 根目录下直接散落的文件自成一组，一并纳入

示例：

```
范围：D:\照片_Leica_M10      剔除：000_成片C
   → 工作在 075_2026_0605 … 098_2026_1006_1011 这些拍摄文件夹上

范围：D:\照片_Leica_M10\000_成片C   剔除：000_成片B
   → 工作在 001_2026_0207 … 等按日期排列的子文件夹上
```

### 3.2 浏览

- 主视图：单张大图
- 底部胶片条：照片横向排列，**按子文件夹分组**，每组有独立的收起 / 展开按钮
- 同一组内按文件名自然排序（相机编号本就是连续的，天然有序）
- 支持在整组之间「连续地」往下看，不需要退出重进

**大图渲染必须基于全尺寸内容，而不是缩略图。** 这是明确要求：

- JPG：直接解码原文件
- DNG：解码文件内嵌的**全尺寸** JPEG 预览（Leica M10 为 5952×3968，GR IV 为 6192×4128）

### 3.3 标记

- 三态：未看 / 选中 / 排除
- 键盘快捷键优先，左右方向键连续过片
- 支持撤销（挑错一张不用重新来找）

### 3.4 输出

- 由用户指定目标文件夹
- 把选中的照片**复制**过去（不移动、不删除，见 4.4）
- 复制时按新规则**重新编号**
- 另需支持 DNG → 全尺寸 JPG 的导出（见 5.3）

## 4. 非功能需求

### 4.1 性能

- 一个 313 张、约 8 GB 的拍摄文件夹，缩略图首屏应在 2 秒内出现
- 全部缩略图后台异步生成，并落盘缓存；第二次打开同一文件夹应接近瞬时
- 大图切换目标 300 ms 以内，可预取相邻若干张

### 4.2 内存

绝不把 25 MB 的 DNG 整个读进内存。必须用随机读取，只取需要的字节区间。

### 4.3 兼容性

- 中文路径与中文文件名必须正常处理
- 以 Windows 为首要平台

### 4.4 数据安全

- 默认**只复制**，绝不移动、绝不删除源文件
- 目标文件夹已存在同名文件时，不得静默覆盖，应提示或自动追加后缀

## 5. 技术方案要点

### 5.1 不需要任何 RAW 解码器（已实测验证）

Java 的 ImageIO 读不了 DNG，这是本项目最大的技术风险。实测拆解后确认：
两类 DNG 内部都存放着相机渲染好的全尺寸 JPEG 预览。

| 相机 | 全尺寸 JPEG 预览 | 小预览 / 缩略图 | 原始数据 |
| --- | --- | --- | --- |
| Leica M10 | 5952×3968，1.44 MB，位于文件偏移 22 KB 处 | 1440×960（147,614 字节）、160×120 | 5984×3992 CFA，24.8 MB |
| Ricoh GR IV | 6192×4128，6.24 MB | 160×120（未压缩） | 6304×4224，29.4 MB |

实现思路：

1. 读文件开头 8 字节，判断字节序（`II` 小端 / `MM` 大端）
2. 定位 IFD0，沿着 SubIFDs 指针遍历所有子 IFD
3. 挑出「Photometric = 6（YCbCr）且 Compression = 7（JPEG）」的图像数据块
4. 读取其 StripOffsets / StripByteCounts，用 `FileChannel` 从该偏移量精确切出字节
5. 把这段字节交给 ImageIO 解码，得到可显示的图像

好处是纯 JDK 实现、零外部依赖，不需要 dcraw / exiftool / libraw。

顺带一提：随机读取在这里不是优化，而是前提。Leica 那个 313 张、8 GB 的文件夹，
网格缩略图只需读每张文件里 147 KB 的小预览，合计约 46 MB。

### 5.2 缩略图与缓存

- 网格与胶片条使用小的内嵌预览（Leica 1440×960，约 147 KB）
- 解码后统一缩放成固定高度，写入磁盘缓存目录
- 缓存键：文件路径 + 文件大小 + 最后修改时间

### 5.3 DNG → 全尺寸 JPG 的导出

直接把内嵌的全尺寸 JPEG 字节原样写出去，**不解码、不重编码**。

- 速度接近文件复制
- 画质等于相机自身的 JPEG 渲染
- 局限：无法自定义画质 / 尺寸 / 色彩空间——但这本来也不是本工具的目标

### 5.4 编号规则（做成可配置）

编号规则不写死，做成可配置项：起始值、步进、名字格式串。
默认 `0%d`：编号值前面加一个 0，即 `010`、`020`、`0230` ……（步进 10）。
步进 10 而不是 1，是为了以后能在中间插入照片而不必整体重编。

### 5.5 GUI 框架

倾向 Swing：JDK 自带、零外部依赖、打包与启动都简单，而本工具界面结构并不复杂
（一个大图区 + 一条横向缩略图带）。JavaFX 表现力更强，但需要引入额外依赖。

## 7. 第一版不做的事

- RAW 解码与调色（不是本工具职责）
- 星级、色标、关键词等重型标记体系
- 云端同步、多用户协作
- 视频文件处理
