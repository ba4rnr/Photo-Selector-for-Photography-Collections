写给后来接手的人——包括几个月后的你自己。先读这份，再动手。

最后更新：2026-10-17 ｜ 组件库现状以最新提交为准

## 一、这是个什么项目

一个本地运行的桌面工具，服务于「拍摄 → 挑片 → 归档成片」里的挑片环节。
Java 25 + Maven，Swing 界面，配色仿 Capture One 的暗色主题。

仓库根目录就是项目根目录，用 Git 管理，远端在 GitHub。

## 三、硬约束（这几条别破）

1. **`core` 与 `io` 不得 import 任何 Swing 类。** `java.awt` 可以用（图像处理需要），
   `javax.swing` 一律不行。这条让业务逻辑能脱离界面测试，也是两个会话能分开干活的前提。
2. **颜色和字体只在 `ui/theme/Theme.java` 里定义。** 别处一律引用常量，不要写死色值。
3. **提交前测试必须全绿**：`mvnw.cmd test`。不要为了让测试通过去改断言的期望值——
   先想清楚是代码错了还是期望错了。
4. **界面的验证方式是离屏渲染成 PNG**，不是靠开窗口肉眼瞅（见第六节）。
5. 类名、方法名用英文；**注释用中文，写"为什么"而不是"做什么"**。

## 四、已经定下来的视觉约定

**配色**（全部取自 Capture One 截图实测，已集中在 `Theme`）：

| 用途 | 常量 | 色值 |
| --- | --- | --- |
| 大图区背景 | `CANVAS` | `#191919` |
| 面板 / 工具栏 / 胶片条 | `PANEL` | `#2D2D2D` |
| 悬停 | `HOVER` | `#363636` |
| 选中 / 激活底色 | `HIGHLIGHT` | `#414141` |
| 激活的图标与文字 | `ACCENT` | `#FF8B16` |
| 正文 / 次要文字 | `TEXT` / `TEXT_MUTED` | `#C3C3C3` / `#A0A0A0` |
| 分隔线 | `BORDER` | `#1A1A1A` |
| 分隔条悬停的高亮 | `DIVIDER_HINT` | `#FFFFFF` |

**只有大图区用 `CANVAS`，其余面板一律 `PANEL`。** 全靠这个拉开层次，全用一个灰度会糊成一片。

**激活态不要用 1 像素细边框。** 在 125%、150% 这类显示缩放下，一条 1 像素的线会落在半个像素上，
左右两条边渲染宽度常常不一样（实测出现过左 1px、右 2px）。Capture One 的做法本来就是
"图标和文字变橙"，照它来。参见 `ToolButton`。

**悬停比激活轻一档**（`HOVER` 对 `HIGHLIGHT`），否则悬停和激活看着一样。

**图标用 Java2D 矢量画**（`ui/theme/Icons`），不引入图片资源：
任意缩放都清晰，颜色能跟着按钮状态走，改配色不用重导图片。

**下拉菜单和滚动条已经换成基础外观（`Basic*UI`）**，别改回系统默认——
系统外观会在弹层上画 1 像素白边、蓝灰底和蓝色的快捷键文字。

**分隔条 4 像素宽**，平时一条几乎看不见的细线，指针压上去才亮出白边（`Splitters`）。

## 五、行为上的约定

**单张照片出问题不要往上抛异常。** 文件不见了、文件损坏，`ThumbnailService` 一律返回一张
画着叉的占位图——素材条一次要取几百张，一张坏图不该让整组都显示不出来。

**绝不在界面线程（EDT）上做文件系统操作或解码。** 解码走 `ThumbnailLoader` 的线程池，
目录扫描走 `MainPanel.scanPool`，结果用 `SwingUtilities.invokeLater` 回 EDT 更新界面。

**素材条是自绘 + 虚拟化的**（`FilmstripPanel`）：只画当前看得见的那十几格，
只为可见的格子请求缩略图。改它的时候别退化成"每张一个组件"。

**缓存键带上文件大小和最后修改时间**（`ThumbnailService`），照片被改过时自动失效。

**竖网格的两块面板共用 `ThumbnailGridPanel`**（目标栏、垃圾桶）：留白、列数、
虚拟化、取图、落点白线都在基类里，子类只实现 `itemCount / sourceAt /
paintCellContent / paintEmptyHint`。素材条是横向分组布局，故意不继承。

**快捷键集中在 `MainPanel` 顶部的 `SHORTCUTS` 表里**，动作名 → 键的一行一项，
`actionFor()` 把名字接到方法上。加键或换键都只改这一处，别在别处再 `bind()` 一次。

**关程序的唯一入口是 `MainPanel.requestClose()`**（× 和菜单"退出"都走它）：
没改动直接退；有改动问「保存 / 不保存 / 取消」；选保存要等后台保存跑完再退。
中间探的"有没有改动"是 `Session.isDirty()`：它拿当前序列 / 垃圾桶 / 编辑表
和上次磁盘基线比较，撤销回原样后会重新变干净。

## 七、动手之前先读一遍现有实现

**别按记忆改代码。** 仓库里的文件可能已经被改过——被上一轮的你、被用户手工调整、
或者被一段重放过的对话。所以每次动手之前：先读当前文件，再按它现在的样子接上去。

这条不是空话。这个项目里好几次出现"我以为那里是 X，实际已经是 Y"的情况
（表头多出的一块预留空间、已经改过的档位表、已经加好的绘制裁剪），
每次都是靠"先读再改"才没有把已有的东西覆盖掉。

配套的两条习惯：

- **提交只加自己改过的文件**，不要 `git add -A`——工作区里可能有别人改到一半的东西
- 小步提交。git 是唯一的同步点，未提交的改动别人看不见

## 八、踩过的坑（省得再踩一遍）

1. **`JTree` 的根节点默认就是展开的**，所以 `expandPath` 是空操作，懒加载事件不会触发。
   根节点的第一层要主动读。
2. **懒加载要给每个文件夹节点塞一个占位子节点**，否则它们在 `JTree` 眼里就是叶子，
   连展开把手都不显示，永远展不开。
3. **改模型之前先把参数校验做完**。`Session.move` 曾经先删再加，参数越界抛异常时
   条目已经从序列里消失——模型被改坏了，而不是"报了个错"。
4. **路径要规范化**（`toAbsolutePath().normalize()`）。同一张照片写成相对路径、绝对路径、
   带 `./` 的形式，规范化之前会被当成三张不同的照片，去重直接失效。
5. **别用 `LinkedHashMap.removeEldestEntry` 做容量淘汰**：那个回调在插入完成**之前**触发，
   判定时还没把新元素算进去，结果会常年超预算一条。改成显式循环淘汰。
6. **一像素的线条在缩放显示下宽度不可控**，别用它做状态提示（见第四节）。
7. **文字抗锯齿会在笔画边缘留下很饱和的彩色过渡色**（实测出现过 `#316897`）。
   写"颜色偏蓝就算"这类断言会误判；要判断"是不是成片"，比如统计某一行里连续的像素长度。
8. **离屏渲染截图时，纯 `Container` 子组件不会被画出来**（分隔条就是），
   因为它们没有 peer。`MainPanelRenderTest.paintScreen` 里手动补画了一次。
9. **测试别不等异步收敛就结束**：后台线程还在写缓存文件，JUnit 删临时目录时会失败。
   要么等它稳定，要么把缓存写到 `target/` 下。
